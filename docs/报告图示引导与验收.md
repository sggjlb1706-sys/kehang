# 报告位置图示引导

用户本次反馈：Notebook可发现候选、Node可检测，但新手不知道在哪里找到报告，希望增加图示、减少文字。原文与三张截图保留在records/report-guide/feedback。截图1实际选中开始菜单目录，规则显示Node缺失、npm/运行未知，不能将用户“可检测”写成该目标通过；截图3仅证明终端列出了Python候选。

本轮保留既有检测能力，在手动报告入口加入三个有实际顺序的图示步骤：

1. Win＋E打开文件资源管理器。已填工具目录时显示该地址、可以复制；没填时只显示自己的解压文件夹示意，不猜D盘或默认下载目录。
2. 文件列表中突出当前应选的report-A.json或report-B.json。复检同时用灰色A示意提醒保留；位置示意明确标注，不证明文件已生成。是否有效仍由原规则、目标和采集时间判定。
3. 在原生文件选择框选择报告。批量A/B和分别导入继续可用，复杂规则与“没有报告”的原因折叠展示。进入复检清空旧的主选择框，保留已导入A事实，避免B标签旁仍显示旧A。

Node路径处增加文件夹/程序文件对照和开始菜单快捷方式属性查找说明。生成命令前拒绝明显不以.exe结尾的目录/快捷方式；带引号粘贴的程序路径会规范化到输入框，使后续报告目标核对一致。没有用文件名推断Node已安装或环境通过。手动命令及下载工具README统一使用A文件名，并在采集成功后提示输出位置；Python/Notebook启动器也明确报告在工具目录task.json旁。

图示为本地HTML/CSS绘制的界面示意，不新增图片、字体、网络依赖或执行接口；目录复制只写剪贴板，拒绝复制时选中地址供Ctrl＋C。未知或旧目录不冒充实际发现位置；切换课程清除旧工具目录显示。本轮不接入其他课程的一键检测、不配置模型服务，不改变13类任务/规则和AI单次同意。

验收索引records/report-guide/acceptance.json包含8组针对性浏览器、13组兼容向导、7组Python本机检测和153单测日志。针对性验证实际执行已有Node固定采集器得到新鲜A/B，核对导入、同目标/原始时间保留；剪贴板成功是实际浏览器API，拒绝是构造场景；旧Python原件是历史报告重分析。390/768/1440排版为同机浏览器模拟，不是实体手机或独立新手验收。

实施中针对性测试首次发现：新支持带引号粘贴Node路径后，输入框保留引号会让实际报告无法匹配；已规范化显示后重新验证成功。之后复核截图中的复检选择框残留A，改为只清空选择框、保留A事实。失败结果文件保留，发现者是实施者，不补造用户逐项Bug反馈。当前独立审查固定提交和最终交付分别见REVIEW.md与仓库外“交付/课航报告图示-20261112”回执；旧版PDF/视频及其他历史结论保留原语境。
