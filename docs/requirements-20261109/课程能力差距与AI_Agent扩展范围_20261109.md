# 课程能力差距与 AI / Agent 扩展范围

日期：2026-11-09。依据用户实际试用反馈：网页和课程分类可以打开，但实际能力距离原课程范围仍有差距，希望补充主流AI及Agent使用，明确包含 [DeepSeek Harness](https://www.deepseek.com/harness/) 这个具体项目。

本文件是下一轮范围与验收建议，不是新增功能已经交付的证明。本轮仅做代码核对、官方资料调研与范围整理；正在使用的 `D:\传智杯\versions\competition-courses-20261108`、旧ZIP及技术PDF不改动。原范围文件和历史验收结论保留原字节。

## 一、当前差距的实际来源

| 原方案/新增需求 | 当前实际实现 | 尚缺的产品能力 |

| Java/JDK | 目录条目，`preparation.py:40`未实现 | 显式JDK，java/javac同源，版本与固定编译运行，不借PATH中的另一套JDK |
| 数据库/SQL | 目录条目，`preparation.py:42`未实现 | 明确DBMS/实例或数据库文件身份、只读连接和固定SELECT；逐步扩展到真实课程数据库 |
| Hadoop/大数据 | 目录条目，`preparation.py:44`未实现 | Linux来宾、JDK、SSH、Hadoop与集群身份组合证据；不能用虚拟机软件通过替代 |
| 学生不知道怎样准备 | `resolve_need`目前是受支持目标的关键词识别；分层指导以固定步骤为主 | 更贴近学习任务的澄清、课程约束确认、针对具体工具的安装/配置/使用路线与报错处理 |
| 主流AI的使用 | 仅固定Qwen离线任务；另有本产品自身的可选报错解释接口 | 面向学生的AI网页/客户端使用、模型API准备与实际调用验证、不同接入路线的差异说明 |
| Agent / Harness使用 | 没有对应课程快照、采集器或操作任务 | 工具与运行时身份、工作目录与权限、模型接入、固定工具调用任务、结果验证与复检 |

源码核对入口：当前正式版 `campuslab/preparation.py`、`rules.py`、`guidance.py`、`diagnosis.py`及`web/index.html`。`rules.task`只受理现有六种任务；本产品能请求AI解释报错，不等于已经提供AI/API或Agent课程。上轮完成的是其限定交付范围，不能据此写整个课程范围已补齐。

“主流”作为代表性工具覆盖，不做未经统计的排名。AI网页/客户端候选可覆盖DeepSeek、通义/Qwen、豆包、ChatGPT、Gemini等；编程Agent候选可含DeepSeek Harness、Codex等。每个具体产品的账号、地区、版本、平台和接入条件以实施时官方资料为准。没有实现固定检测和任务的条目继续标为调研/指导，不能因多放了名称就显示已支持。

本工具继续负责课程环境准备、指导、证据和复检。DeepSeek Harness作为一个具体学习场景接入现有任务体系；本轮需求不意味着把本工具整体迁移到该框架，或让网页任意代理操作电脑。

## 三、DeepSeek Harness 的独立范围

已确认官方提供Windows 64位桌面下载，并链接官方开源仓库与开发者文档；官网标注预览版。[官网](https://www.deepseek.com/harness/)、[官方仓库](https://github.com/deepseek-ai/deepseek-harness)。

两条路线分别设计：

1. **桌面端**：用户明确选择已安装客户端，核对平台、程序身份/版本和本人操作状态。没有依据时，不能把CLI的Node要求套到打包桌面客户端。软件文件存在不证明已登录、模型可用或Agent任务成功。
2. **CLI/Web端**：用户明确选择Node和DSH安装位置，核对包版本、所声明引擎范围、bin入口及实际运行身份，再给手动启动方法。不得用PATH里的另一份Node或全局包凑通过。

截至本次官方源码核对，CLI包`@deepseek-ai/dsh`的Node引擎要求是`>=24.9.0`，需在实施时固定具体上游版本/提交。现有Node演示课允许`>=22且<25`，因此原Node课通过不能直接认定DSH CLI依赖通过。该数字是当前CLI包要求，不是所有Agent或DSH桌面端的通用要求。

本次核实的上游提交为`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，CLI包版本`0.2.2-rc.1`，时间为2026-11-09。具体依据是[CLI包元数据](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/cli/package.json)、[桌面运行时要求](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/README.md#L119)和[可选命令注册](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/README.md#L62)。桌面应用打包自带运行时，不能因系统没有Node或PATH没有dsh就判桌面安装失败。

验收必须分层：

- 所选软件/包和运行时是否存在、版本是否符合、实际身份是否一致。
- 本人选择的工作区及权限是否明确；固定示例采用专用工作目录，说明会读写什么。
- 模型提供方、接入路线和模型标识是否明确。仅有配置提示不证明鉴权、网络或余额可用。
- 是否实际完成了经本人同意的模型调用、固定工具回合，以及产物/测试核验。

官方README中的`npx @deepseek-ai/dsh web`包含取包/启动的可能，不能作为本工具自动检查命令。软件预检优先读本人明确选定位置的包元数据；确需执行版本查询时，只用已核实的固定版本入口。检测、启动、登录、调用模型及执行任务是不同操作，不把它们合并成“已安装即通过”。

不自动读取DSH凭据文件或旧进程密钥，不用完整配置转储取证。用户后续实际运行DSH的任务只取必要工具调用摘要、结果/测试及时间，不收集无关聊天或隐藏推理。实际调用条件或授权缺失时完成其他实现，并保留未知。

## 四、下一轮建议实施顺序

两条主线都要保留：原有专业课程的实际覆盖，以及AI/Agent学习环境。建议先交付三个完整任务：

1. **Notebook数据分析**：明确课程解释器和内核，固定NumPy/Pandas计算与复检，让目录中一个原有核心缺口变成实测能力。
2. **DeepSeek等AI使用与API准备**：先把网页/客户端使用和API调用分开，提供可完成的课程任务、具体操作、错误处理与实际调用状态。模型品牌扩展不能代替这一完整流程。
3. **DeepSeek Harness课程**：桌面/CLI分别给准备路线，完成可取证的本机预检、工作区与权限指导、固定任务和复检。真实调用/登录由本人参与，不冒称代理已验证。

随后补Java/JDK、数据库/SQL的固定纵切；Hadoop按多组件/来宾与集群证据推进。编程Agent和Agent开发框架目录可并行调研，但每个“已实现”必须对应具体运行/验证接缝。最终顺序可依据用户进一步指定的课程和本机可用条件调整，不自行删掉原专业课程范围。

本机只读盘点已发现基础Python中的NumPy/Pandas与Jupyter组件、一个指向该Python的kernelspec、Zulu JDK21及SQLite，给基础课程实测提供条件。此次仅核对安装/版本元数据，尚未运行新Notebook、编译程序或SQL课程验证；这不是新能力已实测。PATH未找到dsh只说明当前命令搜索结果，不等于证明桌面端或其他目录未安装。

新增能力在新的独立目录和codex分支开发，保留当前正式版与材料原字节、真实提交与针对性失败/修复记录。先做新能力的针对性验收，再统一整合回归与材料更新；不要求用户重新完整试用所有旧流程。

## 五、共同完成标准

每一条新增任务都必须能回答：当前是什么学习目标、允许哪条路线、用户选了哪个环境/工具/模型/工作区、已经取得哪些事实、哪些仍未知、下一步本人做什么、怎样证明操作有效并在同一目标复检。

保留固定快照、四状态、原Python/Node/Qwen/PyTorch/VM报告兼容和脱敏分享。AI输出或本人勾选不能覆盖确定性事实；网页使用的本人完成记录与本机自动检测分别显示。模型/API/Agent任务新增模型端点、模型标识与工作区等身份时逐项核对，不能继续只用一个python.exe路径代表全部目标。

持续边界：不自动安装、改系统/网络、启动虚拟机、发布仓库或发送收费模型请求；AI发送前显示实际目的地和内容、允许编辑并经单次明确同意。硬截止仍为2026-11-18 15:00北京时间。未实测、未取得本人素材和实际提交回执继续如实列缺。
