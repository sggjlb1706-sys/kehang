## M0：首轮任务与数据契约

交付：一页 TASK.md，定义首个 Python 基础课程场景、目标用户动作、课程模板和检测报告的最小字段、允许修改范围、检查方法及本轮不做内容。核对现有代码和工具后再决定需要建立哪些目录，不先生成整套空架构。

建议模板字段：模板 ID、版本、目标系统、目标解释器要求、必要软件/包要求、验证步骤。报告字段：目标环境标识、实际解释器路径、检测时间、检查项事实、错误/未知原因。只记录本场景真正使用的字段。

验收：能用一个符合要求的报告、一个缺依赖的报告解释预期差异；明确首个模板是演示样例还是来自真实课程；未决问题不会被伪装成既定要求。

## M1：单场景跑通真实闭环

范围：一个 Windows / Python 场景的页面和完整路径：选模板 → 导入真实检测报告 → 确定性差异分析 → 查看指导 → 重新检测 → 显示前后变化。先采用标准指导，AI 接入前用明确规则说明检查事实。

开发期检测脚本在开发机现有环境运行；正式面向缺 Python 的学生交付必须满足 M4 的独立工具验收。

验收：
- 报告显示明确的解释器路径和时间；使用该解释器获取其包版本。
- 缺失、不符合、无法判断和通过分开；命令启动成功不等于课程程序运行通过。
- 一条真实失败可复现，按指导由用户修复后重新检测可通过。
- 修改前后检查的是同一目标环境、同一模板版本；样例数据不得冒充真实检测。

验收：
- 切换三种模式不改变原始报告、差异结果和验收条件，只改变解释量与操作展示。

## M4：独立工具与完整演示

范围：在缺少课程 Python 的 Windows 环境中能启动的只读检测工具；根据实机条件固定一条大模型部署路径；可导出结果；手机自适应指导；完成两种演示场景。

验收：
- 在没有预装 Python 的测试环境中，检测工具能够独立启动并如实报告缺失，不误报自身嵌入解释器。
- 大模型已在选定实机加载并完成最小推理；记录实际模型、资源条件、版本和验证结果。不能把云端调用算作本地运行成功。
- 新手课程场景：教师发布任务 → 学生进入 → 选择指导程度 → 检测与指导 → 验证。
- 有经验学生场景：已有环境报错 → 检测与文字诊断 → 手动修复 → 复检通过。
- 报告包含必要环境事实和验证结果；分享前可查看并删除不必要的个人路径或日志内容。
- 启动说明、实际检查命令、已知限制可供另一位使用者照做。参赛材料按届时确认的官方要求整理，不编造用户数据或成效。
