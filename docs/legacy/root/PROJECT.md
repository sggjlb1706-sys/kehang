## 产品目标

帮助高校学生依据个人学习目标或课程要求，判断需要怎样的开发环境，发现当前环境差异，获得可以执行和验证的指导，并确认最终能运行。

共享流程：选择目标或课程任务 → 获取本机检测报告 → 比较环境差异 → 生成分层指导及文字报错诊断 → 用户执行步骤 → 复检 → 保存或导出结果。

## V1 范围

| 能力 | V1 交付边界 |
| --- | --- |
| 自主配置入口 | 学生从预置场景开始，或描述目标后映射到已支持的模板；未支持的目标明确说明 |
| 教师任务入口 | 简易创建课程环境模板，发布固定版本，生成课程码或分享链接；学生进入同一配置流程 |
| 统一配置引擎 | 两入口共用模板、检测报告、差异规则和验证逻辑 |
| 三种指导模式 | 新手、标准、快捷可切换；只改变解释程度和步骤展示，不改变环境事实及验收条件 |
| 操作系统 | 先支持 Windows |
| 环境检测 | 明确检测对象及解释器路径，输出事实、版本、检测时间、错误或无法判断原因 |
| AI 诊断 | 以文字错误、环境事实和规则差异为依据，给修复指导和验证方法 |
| 结果验证 | 用真实检查确认运行结果，支持重新检测及导出可分享报告 |
| 大模型演示 | 根据实际设备选定一条可复现的部署与最小推理路径 |
| 手机使用 | 自适应查看指导；配置、检测和运行仍在目标电脑完成 |

首个开发场景建议为“Python 基础课程环境”，大模型部署作为重点演示场景。示例课程和版本要求须明确标为演示数据；没有老师提供真实要求时，不把示例当作学校既定要求。

## 实现建议与关键边界

- 建议：React + Vite + TypeScript 页面、Python FastAPI API、SQLite 保存少量课程模板/任务状态，独立只读检测工具输出 JSON 报告。由 Claude 在 M0 核对现有环境后记录具体版本与最小依赖，避免同时引入第二套技术栈。
- 线上后端检测到的是服务器环境。学生电脑信息来自学生主动运行的本地检测工具及导入报告，不能以服务端检测冒充客户端检测。
- 开发期可先使用 Python 检测脚本；面向没有 Python 的学生交付前，必须提供能独立启动的工具。工具自身打包的 Python 不得被误报为学生课程环境已安装。
- 先检测明确选定的一个目标环境；包版本必须来自该解释器，不把系统其他环境的包混进报告。
- 课程码对应固定模板版本和验收条件。审查期间、学生复检期间，不能悄悄改变同一任务的要求。
- 课程分享链接必须指向学生设备可访问的服务地址；localhost 链接不能当作跨设备分享已完成。
- 本地/受控网络演示与公网真实试用分开验收。公网部署、教师写入身份与访问控制方式在真实试用前确定，不以匿名公开写接口直接上线。
- 事实检测和兼容性比较使用明确规则；AI 负责解释、需求理解及修复建议，不能凭回答把失败改成通过。AI 不可用时，规则结果仍保留，并明确诊断未完成。
